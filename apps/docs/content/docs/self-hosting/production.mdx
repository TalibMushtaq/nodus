## 1. Point DNS at the host

Add an A/AAAA record for your domain.

## 2. Configure `deploy/.env`

```bash
SITE_ADDRESS=nodus.example.com
PUBLIC_RELAY_URL=https://nodus.example.com
ALLOWED_ORIGINS=https://nodus.example.com
SESSION_COOKIE_SECURE=true
POSTGRES_PASSWORD=<strong-secret>
REDIS_PASSWORD=<strong-secret>
```

<Callout type="warn">
  `POSTGRES_PASSWORD` and `REDIS_PASSWORD` are required — Compose refuses to
  start without them rather than falling back to a default. They must be
  URL-safe (no `@`, `:`, `/`, `#`, or whitespace) because Compose interpolates
  them into `DATABASE_URL` and `REDIS_URL` without encoding.
</Callout>

## 3. Bring it up

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up --build -d
```

Caddy obtains and renews the certificate automatically.

## Origin matching

`ALLOWED_ORIGINS` must **exactly** match the browser origin (scheme + host +
port), or WebSocket authentication is rejected. Always open the site at the same
host you set in `PUBLIC_RELAY_URL` / `ALLOWED_ORIGINS`.

<Callout type="info">
  `NEXT_PUBLIC_RELAY_URL` is intentionally left unset. The browser uses this
  origin's `/ws`. Set it only for split deployments where the web app and Relay
  run on different origins.
</Callout>

## Reverse-proxy trust

Caddy runs in front of the Relay, so `TRUST_PROXY` is pinned to `"true"` in
`deploy/docker-compose.yml` for correct client IPs. Do not enable it when
nothing trustworthy terminates the connection.

## Web push

Browser push additionally needs `NEXT_PUBLIC_VAPID_PUBLIC_KEY` as a build arg,
which must match the Relay's `VAPID_PUBLIC_KEY`. See
[Configuration](/docs/self-hosting/configuration).
