# Changelog

## [2026-09-04] - Phase 6: Storage Node Object Store (`services/storage-node`)
**What changed:** Implemented content-addressed object store under `src/store/` with `layout.rs` (bucket prefix scheme `<data_dir>/objects/<prefix>/<hash>`), `write.rs` (atomic temp-write-then-rename, fsync durability, SQLite `storage_objects` tracking, and startup crash recovery), `reconcile.rs` (Phase A metadata-to-disk scan with DEGRADED status marking on missing/corrupted objects, Phase B disk-to-metadata orphan scan with 24-hour grace period deletion per ADR-0005, and 24h periodic background task), `gc.rs` (ADR-0005 garbage collection job retaining 5 most recent versions or <=30 day versions, cascading unreferenced shard object cleanup, 90-day tombstone compaction, and 6h periodic background task), and `mod.rs` (re-exports). Added `blake3`, `uuid`, `walkdir`, and `chrono` dependencies. Updated `main.rs` to initialize the store, run crash recovery, spawn non-blocking background tasks, and listen for termination signals (`tokio::signal::ctrl_c`). Added 18 unit tests (48 total in crate).
**Why:** Phase 6 of the implementation plan — provide durable content-addressed storage for encrypted shards on disk, ensure crash consistency and physical-to-metadata reconciliation (§21 / §21a), and implement the automated garbage collection policy (§29a / ADR-0005).
**Impact:** `services/storage-node` now has fully functional on-disk shard storage, reconciliation, and automated GC.
**Follow-ups:** Wire network transfer endpoints (Phase 10 / Phase 12) to write and read from this store.

## [2026-09-03] - Storage Node: Configurable Backup Directory
**What changed:** Introduced a run-time configurable data directory for the Rust Storage Node. Added `src/config/` with `mod.rs` (first-run detection, `--data-dir`/`NODUS_DATA_DIR` precedence, `~/.nodus/config.toml` read/write), `prompt.rs` (dialoguer interactive first-run flow with `~/NodusBackup` default and create-if-missing), and `validation.rs` (writable-path probe, cloud-sync folder detection, removable/network mount detection, prior-install marker check). Wired config resolution into `src/main.rs` via `clap` (`--data-dir`). Added `dialoguer`, `directories`, `serde`, `toml`, `clap` dependencies. Documented the fixed/user-chosen split in `nodus_implementation_plan.md` §11 and the first-run flow in new §11a; updated the object-store path to `<data_dir>/objects/<prefix>/`; added Phase 5a to `Todo.md`. All relative to the existing docs-only design (the `identity` subdir is reserved for the later node-keypair task).
**Why:** Phase 5a — the node should prompt for a local data directory on first run instead of hardcoding `~/.nodus/objects/`, with unattended-install support so daemon restarts never block, and safeguards against adopting a prior install or a cloud/removable location.
**Impact:** New `src/config/` module and `src/main.rs` boot wiring in `services/storage-node`. New CLI `--data-dir` flag and `NODUS_DATA_DIR` env var. `node.db` is now `<data_dir>/nodus.db`; objects live under `<data_dir>/objects/<prefix>/`. Adds four dependencies to the storage-node crate.
**Follow-ups:** v1 scope boundary — changing `data_dir` after setup is out of scope and needs a migrate-and-verify flow, not a config edit (TODO noted in `docs/architecture`-adjacent plan §11a). Identity subdir task (Phase 5) will populate `~/.nodus/identity/`.

## [2026-09-02] - Phase 4: Protocol Package (`packages/protocol`)
**What changed:** Created the `@repo/protocol` package (packages/protocol) defining the canonical Nodus wire protocol: `src/envelope.ts` (base envelope + `parseMessage` dispatch), `src/version.ts` (schema version constants + compatibility helpers), `src/errors.ts` (generic error envelope, error codes, `ProtocolError`), and per-category message schemas in `src/messages/{control,webrtc,transfer,sync,snapshot}.ts`. Finalized the sync event schema and ordering fields (`src/events/event-types.ts`) with an `EventType` enum and per-type payload validation. Added protocol-local branded types with mapping helpers (`src/types.ts`) so the package is zero-dependency on `@repo/core`. Added a JSON Schema generator (`src/schema-gen.ts`, `pnpm generate:schemas`) emitting `schemas/*.schema.json` for Rust/Go reference. Added 35 vitest round-trip/rejection tests in `tests/`. Wrote `docs/protocol/schema-versioning.md`, `message-catalog.md`, and `event-types.md`, and updated `docs/protocol/README.md` and `Todo.md`.
**Why:** Phase 4 of the implementation plan — define all protocol message types with runtime (zod) validation rather than TS types alone, document the schema versioning strategy, and resolve the "exact sync event schema" and "event ordering guarantees" open items before Phase 8 consumes them.
**Impact:** New package `packages/protocol` (zod v4 runtime-validation, no dependency on core). Adds `schemas/*.json` generated artifacts and `docs/protocol/` documentation. Unblocks Phases 5+ (Rust node, Go relay, relay-client) which build against this contract.
**Follow-ups:** Rust (`serde`) and Go (`encoding/json`) hand-written equivalents must mirror these schemas per `docs/protocol/schema-versioning.md`; regenerate `schemas/` whenever a schema changes.
